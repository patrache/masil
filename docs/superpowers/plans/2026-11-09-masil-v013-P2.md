# masil v0.1.3 P2 — 작업공간과 공유 터미널 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 내 PC 폴더를 masil 안에서 파일 트리·코드 편집(vim 키)·터미널로 쓰고, 오너가 켜면 고른 사람과 종단간 암호화로 공유해 보기 → 제안 → 편집 → 키보드 단계로 함께 고치는 "작업공간" 도구(도구 ID `workspace`)를 만든다.

**Architecture:** UI 없는 순수 패키지 다섯(`wire` 프레임, `wscrypto` 키 교환·봉인, `ot` 글자 단위 OT, `fsroot` 안전한 폴더 접근, `launch`·`hooks`·`audit`·`journal` 보조)을 먼저 만들고, 그 위에 공유 엔진 `share`(오너 `Host` = 문서마다 순번을 매기는 곳 + 1차 권한 검사, 참가자 `Guest`)를 얹는다. 서버는 내용을 못 보는 암호문 중계 DO `WorkspaceHub` + 메타정보 D1 표 2개 + REST 7개만 둔다. 화면은 `internal/ui/workspace`(P0 도구 표면의 한 도구)가 엔진 이벤트를 33ms 마다 비동기 없이 꺼내 그린다.

**Tech Stack:** Go 1.26.6, `CGO_ENABLED=0`; 표준 `crypto/ecdh`(X25519)·`crypto/hkdf`·`crypto/aes`+`crypto/cipher`(AES-256-GCM)·`crypto/ed25519`·`crypto/sha256`·`crypto/rand`, `os.Root`; 승인 모듈 `github.com/ionut-t/goeditor v0.19.0`, `github.com/charmbracelet/x/vt v0.1.0`·`x/xpty v0.1.4`(P0 `termhost` 경유로만), 기존 `github.com/coder/websocket v1.8.15`; 서버 Cloudflare Workers + Hono + zod + D1 + Durable Objects(Hibernation API), vitest `@cloudflare/vitest-pool-workers`.

**Spec:** `docs/superpowers/specs/2026-11-09-masil-v0.1.3-design.md` — B부 전체(B1~B18), 3장, 5장(JX1·JX3·JX4·JX6·JX7·JX8·JX10·JX13·JX14·JX15·JX16), 6장의 B 행, A7.5·A7.7, 8.3 JB1~JB30, "빌더 질문에 대한 결정" 1~7. 함께: `docs/superpowers/specs/2026-11-09-masil-v0.1.4-i18n-design.md` 6.4·6.5·6.6·7.3·7.6·10.3·15절. 계약: `docs/contract/{api,events,data-model,server-architecture,client-architecture}.md`.

## Global Constraints

- 출발점은 P0 0단계가 들어간 `dev/v0.1.3`(빌더 결정 1). 이 계획은 P0 의 i18n F0·도구 표면·`termhost`·브리지 큐가 합쳐진 뒤 Task 19 이후를 시작한다. Task 1~11·13~18 은 P0 없이도 컴파일·시험된다(아래 "P0 에서 받는 것" 표의 것을 쓰지 않는다). Task 12·13 은 P0 서버 Task 8(`alertSpec`)·Task 26(자리 파일·바인딩·리미터)이 먼저 있어야 한다.
- `share` 패키지의 시험은 `package share_test`(외부 시험 패키지)로 쓴다 — `share/sharetest` 가 `share` 를 import 하므로 안쪽 시험에서 쓰면 순환이 된다. 안쪽 상태를 봐야 하면 `share/export_test.go` 로 노출한다.
- 새 Go 모듈 없음. 이 계획이 직접 import 하는 외부 모듈은 `ionut-t/goeditor v0.19.0`(Task 19 만), `coder/websocket`(Task 14 만)뿐. `golang.org/x/crypto` 금지 — 암호는 표준 라이브러리만. `go.mod` 는 P0 가 고친다.
- 기능 플래그: 도구 등록은 P0 기능 플래그 `features.On("workspace")`(환경 변수 `MASIL_FEATURES=workspace`·`all`, 기본 꺼짐) 뒤에서만 허브·팔레트에 보인다(JC21). 시험은 `t.Setenv("MASIL_FEATURES","workspace")`. 서버 라우트는 플래그 없이 더하되 클라이언트가 부르지 않으면 쓰이지 않는다.
- 수치(스펙 그대로): 공동 편집 ≤ 512 KiB, 읽기 전용 512 KiB 초과 ~ 2 MiB, 2 MiB 초과·바이너리(앞 8 KiB NUL 또는 UTF-8 아님)는 열지 않음, 줄 끝 섞임은 읽기 전용, 폴더당 5,000 항목(넘으면 `…외 N개`), 동시 열린 문서 20, 제안 4,000자·대기 20건·사람당 1분 10건, 키보드 10분/**30분(기본)**/1시간/2시간(최대), 오너 15분 무입력 → 키보드 일시 정지, 참가자 60초 넘게 끊김 → 편집 단계로, 참가 요청 5분 만료, 출력 50ms 또는 32 KiB 묶음, 키프레임 10초·새 참가자 때, 참가자 스크롤백 5,000줄, 프레임 최대 256 KiB, 참가자 최대 8명, 사용자당 동시 공유 3개, 오너 끊김 2분 뒤 공유 끝, 외부 변경 확인 0.5초, 자동 저장 2초(기본 끔), 기록 30일, 끝난 공유 D1 행 30일.
- 서버 DO 프레임 한도: 참가자 입력 50프레임/초, 편집 30프레임/초, 제안 10건/분, 오너 출력 2 MiB/초. 넘으면 버리고, 3초 연속 넘으면 `4008 rate_limited` 로 닫는다. 오너 클라이언트도 같은 한도를 따로 지킨다.
- 리미터: `RL_SHARE`(바인딩 10회/60초, `u:<user_id>`, 공유 만들기·초대 더하기) + 공유 만들기는 D1 기준 60분에 10회, `RL_SHARE_WS`(30회/60초, `u:<user_id>`, `/ws`). Workers Rate Limiting 은 주기가 10·60초뿐이라 60분 한도는 D1 로 센다. **바인딩은 P0 Task 26 이 만든다**(`RL_SHARE` 7113 10/60, `RL_SHARE_WS` 7112 30/60, `LimiterName` 포함) — P2 는 `wrangler.jsonc`·`lib/ratelimit.ts`·`app.ts`·`index.ts` 를 고치지 않는다.
- 암호: X25519 + HKDF-SHA256 + AES-256-GCM + Ed25519, 공약(commitment) 단계가 있는 6자리 확인 숫자. 편집·키보드는 확인 필수, 보기·제안은 `확인 없이 허용`(→ `미확인` 표시) 가능. 압축하지 않는다.
- 서버는 내용·경로·파일 이름·명령·화면을 저장도 기록도 하지 않는다. D1 에는 메타정보만, DO 메모리에는 최근 키프레임 묶음 암호문만(DO 저장소에 쓰지 않음).
- 문구: 새 문구는 전부 `internal/i18n/locales/ko/workspace.toml`(+ 같은 PR 의 `en/workspace.toml`). 새 패키지의 한글 리터럴 0개(P0 래칫). 보안 경고·확인 대화상자의 "무엇을 하는지" 문장·약관 안내는 `no_truncate = true`, 경고·법적 문구는 `legal = true`. 사람 이름은 `{name}님` + 고정 조사(D8). 번역하지 않는 것: 키 이름(`ctrl+\`), 명령 이름(`claude`, `/tools`), 사용자 글·파일 이름.
- 서버는 사용자용 완성 문장을 만들지 않는다: alert 는 `template.id` `workspace.invite`·`workspace.attention`(+ `docs/contract/i18n/alert-templates.json` 등록), 오류는 기존 `code`.
- 화면에 그리는 남의 글자(파일·폴더 이름, 공유 이름, 표시 이름, 터미널 제목, 제안 글)는 그리기 전에 `textwidth.Sanitize`. 폭은 `x/ansi` 하나, 한글 2칸.
- 필수 화면 크기: 200×60, 120×40, 80×24, 50×20, 40×14(`uitest.Required` + `{40,14}`). 초소형에서는 요약·즉시 끊기·제안 처리만.
- 기존 골든 무변화(기준 v0.1.2 태그) — 예외 없음. 플래그가 기본 꺼짐이라 `ws.*` 팔레트 명령도 기존 목록 골든에 안 보인다. 출시 기능 집합을 켜며 바뀌는 도움말·팔레트 목록 골든은 P0 Task 31 이 한 번에 갱신한다(JX9).
- 로그 금지: 터미널 입출력 바이트, 파일 내용, 제안 글, 키, 확인 숫자를 `slog` 에 쓰지 않는다. 기록 파일(audit)에만 B8.5 목록대로.
- 로컬 파일 권한: 기록 `~/.config/masil/workspace-audit/<공유ID>.jsonl` 0600(폴더 0700, 덧붙이기만), 복구 일지 `<캐시>/workspace-journal/…` 0600, claude 임시 설정 0600.
- 배포·태그·원격 D1/DO 생성은 하지 않는다(오너 건별 승인). 서버 시험은 로컬 vitest 만(빌더 결정 7).
- 커밋 메시지는 영어, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. 문서·화면 문구는 한국어, 식별자·주석은 영어.

## Review Focus

1. **오너 노트북 잠자기·와이파이 끊김(2분 안/밖)** — 기대: 2분 안에 돌아오면 참가자는 숫자 비교 없이 `hs_resume` 으로 이어지고 키보드 만료 시각은 그대로(연장되지 않음), 2분이 넘으면 서버가 공유를 끝내고 오너가 돌아와도 저절로 다시 열리지 않는다. → Task 13 `owner gone 2 minutes ends the share`, Task 16 `TestHostResumeWithinGraceKeepsExpiry`.
2. **이모지·결합 문자·CRLF·BOM 이 섞인 파일을 여럿이 동시에 고침** — 기대: 위치는 rune 단위로 모든 사람에게 같고, 저장하면 CRLF·BOM 이 그대로, 편집기 커서는 그래핌 경계에 선다. → Task 5 `TestFuzzConvergence`(알파벳에 `👩‍💻`·`한`·`é`), Task 9 `TestWriteTextRestoresCRLFAndBOM`, Task 19 `TestAdapterEmojiColumns`.
3. **출력 폭주(`cat big.log`, `yes`, claude 스트리밍)** — 기대: 오너 PTY 는 막히지 않고, 오너 클라이언트가 2 MiB/초를 넘기면 밀린 출력을 버리고 다음 키프레임으로 건너뛰어 참가자 화면이 깨진 채 남지 않는다. → Task 17 `TestTermBurstFallsBackToKeyframe`.
4. **외부 편집기가 "새 파일로 쓰고 이름 바꾸기"로 저장하거나 지웠다 다시 만듦(연달아)** — 기대: 바뀐 것마다 정확히 한 번 합쳐지고, 지웠다 다시 만들면 `디스크에서 지워짐` 상태가 풀린다. → Task 18 `TestDiskRenameWriteMergedOnce`, `TestDiskDeleteRecreate`.
5. **악의적인 오너가 보낸 파일 이름·터미널 제목·표시 이름(ANSI, U+202E, 0폭 문자)** — 기대: 참가자 화면에서 모두 `Sanitize` 를 거쳐 테두리가 어긋나지 않고, 키보드 허용 확인은 표시 이름이 아니라 핸들(ASCII)로만 맞춘다. → Task 23 `TestGuestTreeSanitizesHostileNames`, Task 21 `TestKeyboardConfirmRequiresHandle`.
