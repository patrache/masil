# masil v0.1.3 P3 — 아키텍처 설계 도구 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 방에서 함께 그리고, 결정적으로 시뮬레이션하고, 비용을 추정하고, Mermaid·D2·Terraform·글자 스냅숏으로 내보내는 터미널 아키텍처 설계 도구(도구 ID `arch`)를 만든다.

**Architecture:** UI 없는 순수 패키지 다섯(`archdoc` 모델·검증·객체 사상·되돌리기·개인 파일, `archsim` 결정적 엔진 + `archsim/pricing` 가격표, `archdraw` 격자 그리기·선 경로·적중 검사, `archexport` 내보내기)을 먼저 시험만으로 완성하고, 그 위에 도구 표면 인스턴스 `internal/ui/arch` 를 얹는다. 공유 설계는 P0 의 `CollabHub`(서버 순번 + 필드 LWW)를 쓰고, P3 는 `arch` 문서 종류 검증기·`arch.*` 카드 스키마만 서버에 채운다(댓글 서버는 P0).

**Tech Stack:** Go 1.26.6(표준 라이브러리 + 기존 bubbletea v2·lipgloss v2·x/ansi·x/exp/golden), TypeScript Worker(Hono·zod·vitest-pool-workers), D1.

**Spec:** `docs/superpowers/specs/2026-11-09-masil-v0.1.3-design.md` — C2 전체, C1.1·C1.2·C1.4(공통 바탕 중 이 기능이 쓰는 것), A8(도구 입구), 3장·5장(JX1·JX3·JX4·JX14·JX16), 8.4 JC1~JC14·JC21·JC22, 끝의 "빌더 질문에 대한 결정". `docs/superpowers/specs/2026-11-09-masil-v0.1.4-i18n-design.md` — 6.4(카탈로그), 6.5 D8, 6.6(폭·`no_truncate`), 7.6(서버 문구), 9.3(래칫), 15절.

## Global Constraints

- Go `1.26.6`, `CGO_ENABLED=0` 로 darwin·linux·windows 빌드(`make cross`). P3 는 **새 Go 모듈·npm 패키지를 하나도 더하지 않는다**(JX16): 엔진·렌더·내보내기 = 표준 라이브러리 + 기존 의존성(lipgloss, x/ansi, textwidth).
- 새 Go 패키지의 한글 문자열 리터럴 **0개**(`internal/i18n/legacy_literals.txt` 래칫 `TestHangulLiteralRatchet`; 시험·`testdata`·`*_gen.go`·`internal/ui/uitest/` 제외). 사용자 문구는 전부 `internal/i18n/locales/ko/archcanvas.toml`(원본, P0 Task 4 가 만든 빈 영역 파일을 Modify) + `en/archcanvas.toml`(같은 PR). 보안·확인·약관·추정 고지 문구는 `no_truncate = true`, 경고·법적 문구는 `legal = true`.
- 서버는 사용자용 완성 문장을 만들지 않는다: 알림 = `template.id` + 인자(`doc.comment_mention` 은 P0 Task 29), 오류 = 기존 `code` + `detail`.
- 사용자 라벨·댓글·문서 제목·카드 안 글은 그리기 전에 `textwidth.Sanitize`. 폭은 `textwidth`(x/ansi), 한글 2칸.
- 한도(JC14): 설계 노드 300 · 연결 1,000 · 상자 중첩 3단 · 설계 JSON 1MB · 카드 데이터 직렬화 16KB · 카드 `body` 1..4000 · 카드 미니 그림 최대 8줄 × 60칸 · 가져오기 1MB.
- 결정성: 같은 설계·같은 시드 → darwin/arm64 와 linux/amd64 에서 같은 정수(ms, 0.1% = permille, 달러). 표준 라이브러리 난수·`math.Exp`·`math.Log`·삼각함수 금지(아키텍처별 asm), `x*y+z` 꼴 부동소수 식은 `float64(x*y)+z` 로 FMA 합침 차단, map 은 정렬된 ID 순서로만 순회.
- 성능 목표: 즉시 분석 노드 300 에서 5ms, 한 화면 그리기 노드 300·연결 1,000 에서 8ms, 끄는 동안 한 프레임 노드 50 에서 8ms(M1 기준), 설정 변경 → 결과 0.1초 안. 시간 실행 0.1초 tick, 60~600초, 재생 x1~x16.
- 숫자는 늘 "추정" — 지표 줄·카드·도움말·스냅숏에 `(추정)` 또는 `~` 와 가격표 기준 날짜. 가격표는 앱에 내장(네트워크 조회 없음), AWS 리전 4(ap-northeast-2, us-east-1, eu-central-1, ap-northeast-1)·인스턴스 약 30종, GCP·Azure 리전 2·약 10종, 파일마다 출처 URL·기준 날짜, 손으로 옮김. 로고·아이콘 없음.
- 개인 설계 `~/.config/masil/arch/<이름>.json`(0600, `config.WriteFileAtomic`), 서버로 안 감. 공유 설계 = `collab_docs.type = "arch"`.
- 마우스로 되는 것은 모두 키로(`ui.mouse=false` 에서도). 캔버스는 masil 전역 키(`ctrl+k`, `ctrl+t`, `ctrl+c`, `tab`, `shift+tab`, 그리고 모드 취소 뒤의 `esc`)와 도구 전환 `[`/`]`(A8.3)를 가로채지 않는다.
- 기능 플래그 `features.On("arch")`(JC21) 뒤에서 만든다: 플래그가 꺼지면 허브·팔레트·카드 `enter` 에 `arch` 가 없다(카드 `Lines` 는 그려도 되고 `Open` 은 nil). 출시 기능 집합을 켜는 것과 목록 골든 갱신은 P0 Task 31.
- 계약은 더하기만, 코드보다 문서 먼저(각 Task 가 자기 계약 절을 같은 커밋에). 서버 시험은 로컬 vitest(`@cloudflare/vitest-pool-workers`)만, 배포·새 DO·D1 원격 마이그레이션은 하지 않는다(오너 건별 승인).
- 기존 골든은 바뀌지 않는다(도구를 안 연 화면). 코드 식별자·주석·커밋 메시지는 영어, 문서는 한국어.

## Review Focus

1. **동시 구조 편집이 만든 깨진 그림**: A 가 노드를 지우는 동안 B 가 그 노드에 연결을 잇거나, A 가 상자 X 를 Y 에 넣고 B 가 Y 를 X 에 넣으면(서버가 하나씩은 통과시켜도 오프라인 재전송·되돌리기로 생길 수 있음) 모두의 화면이 패닉 없이 **같은** 그림을 보여야 한다 — 끊긴 연결은 숨기고 점검에 "연결 안 된 노드"로, 부모 순환은 정해진 규칙으로 끊는다. → Task 2 `TestFromObjectsDanglingAndCycles`.
2. **퇴화 숫자**: 인스턴스 0, 요청당 CPU 0, 대역폭 0, 경로 비율 합 > 100%, RPS 0 또는 20억, 자동 확장 min > max — 검증을 거치지 않은 공유 문서·카드 사본으로도 엔진에 들어온다. NaN·음수·0 나눗셈·int 넘침 없이 정수 결과와 "과부하"/"꺼짐"이 나와야 한다. → Task 7 `TestAnalyzeDegenerateInputs`, Task 8 `TestTimedDegenerateInputs`.
3. **제스처 도중의 방해**: 끄는 도중 창 크기·모드가 바뀌거나, 끌던·설정 중이던 노드를 남이 지우거나, 연결이 끊기거나, 포커스가 다른 칸으로 가면 유령 상자가 남지 않고 오래된 op 를 보내지 않으며 설정 패널은 "삭제됨" 안내와 함께 닫혀야 한다. → Task 17 `TestDragCancelledByResizeAndRemoteDelete`, Task 18 `TestRemoteDeleteClosesPanel`.
4. **남이 보낸 카드·사본의 손상**: 스키마는 맞지만 미니 그림 줄이 60칸보다 넓거나 ANSI·양방향 문자가 들었거나, 설계 사본이 한도를 넘거나, `v` 가 미래 버전인 카드 — 채팅 화면이 깨지지 않고 `body` 대체나 안전하게 잘린 그림으로 보여야 한다. → Task 26 `TestCardRendererHostileData`.
5. **로컬 파일 이름과 덮어쓰기**: 개인 설계 이름에 `/`·`..`·`\`·NUL·한글·280바이트, 같은 이름 저장, 내보내기 대상 파일이 이미 있음 — 설정 폴더 밖에 쓰지 않고, 묻지 않고 덮어쓰지 않아야 한다. → Task 4 `TestStoreNamesAreSafe`, Task 20 `TestExportAsksBeforeOverwrite`.
