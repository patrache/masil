# masil v0.1.3 P0 공통 기반 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 다섯 도구(P1~P4)와 0.1.4 이관(P5)이 올라설 바닥 — i18n F0(카탈로그·생성기·열린 언어 관문·`Accept-Language`·서버 alert 템플릿), 기다리지 않는 실시간 브리지 줄, `internal/termhost`(화면 전환·tmux 팝업·내장 패널)와 `termpane` 화면, 도구 표면(허브·`ctrl+t`·팔레트·`/tools`·넓게 보기), `internal/secrets`, `kind:"card"` 메시지, `CollabHub` 방 문서 공동 편집, Go 1.26.6·고정 의존성 — 을 `dev/v0.1.3` 에 먼저 넣는다.

**Architecture:** 모든 공용 지점은 **등록부**로 연다: 도구는 `ui.RegisterTool`, 카드는 `ui.RegisterCard`, 서버 카드 스키마는 `server/src/lib/cards/<도구>.ts`, 문구는 영역별 TOML(`internal/i18n/locales/<언어>/<영역>.toml`) → 영역별 생성 파일. 셸(`ui/app`·`layout`·`keymap`·`palette`)·서버 조립(`app.ts`·`wrangler.jsonc`)·계약 문서·`CollabHub` 는 P0 만 고치고, 다른 줄기는 등록부와 P0 가 미리 만들어 둔 빈 자리(라우터 파일·영역 파일·마이그레이션 번호)로만 붙는다. 비동기 결과는 새 `ui.Context.Post`(막히지 않는 줄)로 화면에 온다. 도구는 기능 플래그(`internal/features`) 뒤에 숨어 있어 플래그를 켜기 전까지 기존 화면은 한 글자도 바뀌지 않는다.

**Tech Stack:** Go 1.26.6 · bubbletea/v2 v2.1.1 · lipgloss/v2 v2.0.6 · `github.com/charmbracelet/x/vt v0.1.0` · `github.com/charmbracelet/x/xpty v0.1.4` (간접 `creack/pty v1.1.24`, `x/conpty v0.2.0`) · `github.com/ionut-t/goeditor v0.19.0` · `golang.org/x/text v0.43.0`(`language` 추가) · `golang.org/x/sys v0.49.0` · `godbus/dbus/v5 v5.1.0` · BurntSushi/toml v1.6.0 · 서버 Hono 4.13.16 · zod 4.6.7 · wrangler 4.157.0 · vitest 4.1.12 + `@cloudflare/vitest-pool-workers` 0.23.0.

**Spec:** `docs/superpowers/specs/2026-11-09-masil-v0.1.3-design.md`(이하 **설계서** — 3장, 5장, 6장, A6~A9, C1, 7장, 8장, "빌더 질문에 대한 결정") 와 `docs/superpowers/specs/2026-11-09-masil-v0.1.4-i18n-design.md`(이하 **i18n** — 6.1~6.4, 6.6, 7.2~7.3, 7.6, 9.1~9.3, 10장, 15절). 실행자는 자기 Task 의 절을 두 설계서와 `docs/contract/*.md` 에서 함께 연다.

## Global Constraints

- 출발점: v0.1.2 태그가 붙은 main → 통합 브랜치 `dev/v0.1.3`. P0 의 모든 Task 는 `dev/v0.1.3` 에 먼저 들어간다. 골든 무변화 기준은 v0.1.2 태그 시점.
- **Go 1.26.6**, `CGO_ENABLED=0` 로 darwin·linux·windows 크로스 빌드(`make cross`). `toolchain` 지시어 없음.
- 새 Go 모듈은 정확히 `github.com/charmbracelet/x/vt v0.1.0`, `github.com/charmbracelet/x/xpty v0.1.4`(간접 `github.com/creack/pty v1.1.24`, `github.com/charmbracelet/x/conpty v0.2.0`), `github.com/ionut-t/goeditor v0.19.0` 셋뿐. 암호는 표준 라이브러리, 키체인은 `golang.org/x/sys`·`godbus/dbus/v5`·`/usr/bin/security`. `go.yaml.in/yaml/v3` 는 시험 전용 그대로.
- 계약은 **더하기만**. 0.1.2 클라이언트가 같은 서버에서 계속 동작해야 한다. 계약 문서를 코드보다 먼저 고친다(Task 2).

- 새 패키지는 **한글 문자열 리터럴 0개**(Task 6 래칫). 아직 이관 안 된 패키지(`ui/app`, `ui/keymap`, `ui/palette`, `slash`, `ui/chat`, `ui/settings` 등)에 P0 가 더하는 문구도 카탈로그로. 영역 파일: `tools.toml`(허브·자격증명), `termpane.toml`(패널·접두키·종료 확인·복귀 토스트), `leetcode.toml`, `lazygit.toml`, `workspace.toml`, `archcanvas.toml`, `apitest.toml`(+ 이 계획의 `common.toml`, `alerts.toml`). `claude.toml` 은 만들지 않는다. ko 원본 + en 은 같은 PR, zh-Hans 는 비어도 된다.
- 보안 경고·확인 대화상자의 "무엇을 하는지" 문장·약관 안내 키는 `no_truncate = true`, 경고·법적 문구는 `legal = true`.
- 번역하지 않는 것: 키 이름(`ctrl+\`, `ctrl+t`), 명령 이름(`/tools`), HTTP 메서드·상태 문구·헤더 이름, 사용자 라벨·이름·글.

## Review Focus

1. **`ctrl+\` 가 다른 키 이벤트로 들어오는 터미널**(바이트 0x1c 가 `ctrl+4` 나 `ctrl+\\` 문자열로 해석) — 사람은 어느 터미널에서든 접두키가 먹고 패널에 갇히지 않길 기대한다. → Task 16 `TestPrefixAcceptsCtrlBackslashVariants`.
2. **패널 안 프로그램이 스스로 끝남**(lazygit `q`, 셸 `exit`) — 사람은 포커스가 masil 로 돌아오고 탭에 `끝남 · 종료 코드 0` 이 보이며 키가 죽은 패널로 가지 않길 기대한다. → Task 16 `TestPaneChildExitReleasesFocus`.
3. **프로그램이 도는 중 창을 TooSmall 로 줄였다 키움** — 사람은 프로세스가 살아 있고, 다시 키우면 그 크기로 다시 그려지길 기대한다(패닉·0 크기 Resize 없음). → Task 14 `TestPaneSurvivesZeroSize`, Task 16 `TestPaneSurvivesTooSmallAndBack`.
4. **키체인 허용 창에서 거절·잠긴 모음 해제 취소** — 사람은 크래시나 무한 재시도 대신 "키체인을 쓸 수 없어요" 동의 질문을 기대한다. → Task 22 `TestPutKeychainDeniedNeedsConsent`.
5. **보내지 못한 편집이 있는 채 다시 붙었는데 그사이 강퇴·문서 삭제** — 사람은 내 편집이 말없이 사라지지 않고 "보내지 못한 편집 n개" 로 보존되며 같은 편집을 끝없이 다시 보내지 않길 기대한다. → Task 30 `TestSessionKickedKeepsPending`.
