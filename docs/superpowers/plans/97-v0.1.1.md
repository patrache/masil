## 오너 결정 (2026-11-08)
- **D7 시스템 메시지는 스레드 루트가 될 수 없다.** 시스템 메시지(채널 생성, 고정 알림 등 kind=system)에는 답글·리액션 불가.
  - 서버: 시스템 메시지를 parent 로 한 답글 생성, 리액션 추가를 거부한다(기존 오류 체계 안에서 적절한 코드, 예: 400/422 계열 — docs/contract/api.md 의 오류 규칙을 따르고 api.md 에 명시).
  - 클라이언트: 시스템 메시지는 선택은 되지만 enter 로 스레드가 열리지 않고 리액션 메뉴/단축키도 막힌다(react/edit/pin/copy 를 막는 기존 코드와 같은 자리). 도움말 줄에도 스레드 키가 안 보이게.
- **D8 '님'은 이름에 붙여 쓴다.** "하나님이" (O) / "하나 님이" (X). 서버 alert 제목·본문 등 사용자에게 보이는 모든 서버 문구를 감사해서 맞춘다. 클라이언트는 이미 붙여 씀 — 클라이언트에도 띄어 쓴 곳이 있으면 같이 고친다.

## 릴리스/CI/문서
- R1 .github/workflows/release.yml: GitHub 릴리스 다운로드 504 장애(2026-11-08)로 goreleaser-action 의 바이너리 다운로드가 실패했다. goreleaser 설치를 장애에 강하게: 예) 다운로드 재시도 후 실패 시 `go install github.com/goreleaser/goreleaser/v2@v2.19.0` 대체(proxy.golang.org) 하거나 처음부터 go install 로 설치하고 `goreleaser release --clean` 실행. 액션 SHA 고정 규칙(pending 2번, test 가 YAML 을 읽어 확인)을 지킨다.
- R2 install-smoke: scripts/install.sh 의 내려받기에 재시도(curl --retry 5 --retry-all-errors 등, wget 도), scripts/install.ps1 도 재시도. 실패 메시지가 "비공개이거나 버전이 없습니다" 만 말하지 말고 HTTP 오류일 수 있음을 알린다.
- R3 tap: patrache/homebrew-tap 의 기본 브랜치는 `formula` 다(main 직접 push 가 hook 에 막힘). release.yml homebrew-tap 작업이 기본 브랜치를 checkout/push 하는지 확인하고, 명시가 필요하면 ref: formula. 주석에 적는다.
- R4 문서: 계획 06(라인 ~1277, Task 13 item 12)과 spec(라인 ~124)의 "라이선스 미정" 문구를 MIT 로. 계획 06 Task 14~18 의 관문 시험 명령에 `-ldflags "-X github.com/patrache/masil/internal/version.Version=0.1.0-dev"` 추가. 계획의 `go version -m | grep DefaultServer=` 검사는 -trimpath 로 맞을 수 없으니 scripts/check-release-binary.sh 로 대체 표기.
- R5 internal/version 등 버전 표기는 태그에서 오므로 코드에 0.1.1 을 박지 않는다.
