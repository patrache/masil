## 1. 의도 — 왜 하는가

오너: "전세계 사람들이 보면 좋겠다." **[오너 결정]**

지금 masil 은 README·화면·알림·오류 문구가 전부 한국어다. 한국어를 못 읽는 사람은 설치 방법부터 막힌다. 그래서 v0.1.4 에서 두 가지를 한다.

1. **README 를 영어로**: `README.md` 는 영어, 지금의 한국어 README 는 `README.ko.md` 로 옮겨 그대로 유지하고, 두 파일 맨 위에 서로를 가리키는 언어 링크를 둔다. **[오너 결정]**
2. **앱 화면을 3개 언어로**: 한국어(지금) + 영어 + 중국어. 중국어는 **간체(zh-Hans, 중국 본토·싱가포르식 글자) 먼저** **[오너 결정 — 간체 우선은 대화 중 내가 정하고 오너가 받아들임]**.

일정 **[오너 결정]**: 0.1.4 는 0.1.3(다섯 기능)과 **병렬로** 개발한다. 둘 다 0.1.2 출시 뒤 시작. 다국어의 **기반(문구 저장소 = 카탈로그)을 먼저** 깔고, 0.1.3 의 새 코드는 첫날부터 그 기반을 쓴다.

### 1.1 성공의 모습

- 영어 사용자가 GitHub 에서 masil 을 보고, 영어 README 만 읽고 설치·가입·채팅까지 간다.
- `LANG=en_US.UTF-8` 인 새 PC 에서 `masil` 을 처음 켜면 영어로, `zh_CN` 이면 간체 중국어로, `ko_KR` 이면 한국어로 뜬다. 설정에서 언제든 바꾸고, **바꾸는 즉시** 화면 전체가 그 언어로 바뀐다(재시작 없음).
- masil 이 꺼져 있을 때 오는 OS 데스크톱 알림(데몬)도 같은 언어로 뜬다.
- 영어·중국어 화면도 한국어 화면만큼 "짱짱 이쁘다" — 200×60 부터 초소형까지 테두리가 어긋나거나 글자가 겹치지 않는다.
- **한국어 화면은 한 글자도 바뀌지 않는다.** 기존 한국어 골든(화면 스냅샷) 1,372개가 이 작업 내내 그대로 통과한다.

### 1.2 목표 (Goals)

- G1. README 영어화 + 한국어판 유지 + 언어 링크 + README 를 읽는 시험 갱신.
- G2. 앱의 사용자에게 보이는 모든 문구(TUI·CLI 출력·OS 알림·오류·도움말·명령 팔레트·슬래시 명령 안내)를 ko / en / zh-Hans 로.
- G3. 언어 선택: 설정 + 첫 실행 기본값을 OS 언어에서.
- G4. 날짜·시각·숫자·기간 표기를 언어별로.
- G5. 서버가 만드는 사용자용 문구(알림 제목·본문, 집중 모드 요약, 기본 채널 이름)를 언어별로.
- G6. 언어별 골든 시험, 폭(칸 수) 검사, 번역 누락 검사, "한국어 문자열을 코드에 새로 박지 못하게" 막는 검사.
- G7. 번역 작업 흐름(초벌 → 원어민 검수 → 출시 관문)과 용어집.
- G8. 0.1.3 다섯 기능이 첫날부터 카탈로그를 쓰고, 기존 문구는 패키지 단위로 옮기되 0.1.3 을 막지 않는다.

### 1.3 논골 (이번 범위 아님) **[제안]**

- 번체 중국어(zh-Hant), 일본어 등 다른 언어. 오른쪽→왼쪽 언어(아랍어·히브리어). — 구조는 늘릴 수 있게 하되 이번엔 3개만.
- `README.zh-Hans.md`(중국어 README). 오너가 말한 것은 영어 README 다.
- 사용자 글·메시지의 자동 번역.
- 슬래시 명령 이름(`/poll`, `/focus` …)·CLI 하위 명령(`masil login` …)·키 이름(`enter`, `ctrl+k`)의 번역. 이것들은 모든 언어에서 영어 그대로다.
- 운영자 CLI(`masil admin …`, `internal/admincli`)의 번역. 운영자는 오너 한 사람이고 한국어를 쓴다. 한국어로 남긴다.
- 로그 파일 문구의 번역. 로그는 개발자용이다(새로 쓰는 로그 문구는 영어로 쓴다).
- 계약 문서(`docs/contract/*`)·설계서·계획서의 번역. 이 문서들은 한국어로 남는다.
- 중국어 병음으로 사람·채널 검색.
- LeetCode 문제 본문 번역(0.1.3 기능). 문제 본문은 LeetCode 가 준 언어 그대로다.

### 1.4 안티골 (돌아가도 실패인 것)

- **한국어 화면이 바뀌는 것** — 띄어쓰기 하나, 조사 하나라도. 다국어 작업이 기존 사용자에게 회귀를 주면 실패다.
- 기계 번역 티가 나는 영어·중국어. 특히 보안 경고(0.1.3 의 Claude 키보드 넘기기 경고 등)가 원문과 뜻이 다른 것.
- 출시된 언어에서 한 화면 안에 한국어와 영어가 섞여 나오는 것(번역 누락이 그대로 새는 것).
- 영어 문구가 길어서 초소형·위젯 모드의 탭·상태줄·버튼이 잘리거나 테두리를 밀어내는 것.
- 언어를 바꾸려면 재시작해야 하는 것, 바꾸는 순간 입력 중이던 글·스크롤 위치가 사라지는 것.
- 이미 한국어로 잘 쓰던 사람이 업데이트 후 갑자기 영어 화면을 보는 것(개발자 PC 는 `LANG=en_US` 인 경우가 많다).
- 번역 문구를 통해 터미널 제어 문자나 OS 알림 스크립트를 끼워 넣을 수 있는 구조.

## 2. 제약

- **Go 1.26(1.26.6 상향 승인됨 [오너 결정])**, `CGO_ENABLED=0` 크로스 빌드(macOS·Linux·Windows). cgo 가 필요한 다국어 라이브러리는 못 쓴다.
- **새 모듈 추가 없음 [제안]**. `golang.org/x/text v0.43.0` 은 이미 직접 의존성이다(지금은 `unicode/norm` 만 씀). 같은 모듈의 하위 패키지(`language`)를 더 쓰는 것은 새 모듈이 아니다. 단 `client-architecture.md` 1.2 용도 표와 `internal/deps/deps.go` 고정 목록에 한 줄 추가가 필요하다 — 계약 문서 수정이므로 오너 승인 사항.
- 계약 문서를 고쳐야 하는 곳(코드보다 문서 먼저, 오너 승인): `client-architecture.md` 1.2·2.1·2.2·3.3·4.9·5.3.2·10장, `api.md` 0.1·0.3·2장(`Alert`), `events.md` 4.7.
- **D8: '님'은 이름에 붙여 쓴다**("하나님이" O, "하나 님이" X). 한국어 카탈로그·서버 문구 모두. **[오너 결정, v0.1.1]**
- 폭 규칙(원 설계서·`client-architecture.md` 8장): 한글·한자·이모지는 2칸, 폭 계산은 `x/ansi` 하나로. 모호 폭 문자를 2칸으로 그리는 터미널 설정은 지원하지 않는다.
- 서버는 Cloudflare Workers/DO/D1. 계약 변경은 **더하기만**(하위 호환) — 0.1.3 이하 클라이언트가 계속 동작해야 한다.
- 배포·태그·과금 리소스는 오너 건별 승인. 이 문서는 아무것도 배포하지 않는다.

## 5. README (G1)

### 5.1 파일

- `README.md` — 영어. 지금 한국어 README 와 **같은 장 구성**(설치 / 시작하기 / 화면 모드 / 주요 키 / 알림 데몬 / 설정 / 제거 / 문제 해결 / 로컬 개발 / 라이선스) + "Language" 설정 설명 1절 추가.
- `README.ko.md` — 지금의 한국어 README 를 옮기고 같은 "언어" 설명 1절 추가.
- 두 파일 첫 줄 아래에 언어 링크 한 줄 **[제안]**:
  - `README.md`: `**English** · [한국어](README.ko.md)`
  - `README.ko.md`: `[English](README.md) · **한국어**`
  - 나중에 중국어 README 를 더하면 같은 줄에 `简体中文` 을 붙인다.
- 영어판에서 바뀌어야 하는 사실(번역이 아니라 내용): macOS 알림이 뜨는 앱 이름은 OS 언어를 따라 "Script Editor" 로 보인다. `masil daemon status` 출력 예는 영어 출력으로. 한국어판의 출력 예는 한국어 그대로.

## 6. 앱 다국어 — 클라이언트 (G2·G3·G4·G6)

### 6.1 언어 이름과 코드

| 코드(BCP 47) | 화면에 보이는 이름(항상 그 언어 자신의 이름) | config 값 |
|---|---|---|
| `ko` | 한국어 | `ko` |
| `en` | English | `en` |
| `zh-Hans` | 简体中文 | `zh-Hans` |

- 언어 목록에서는 언제나 "그 언어 자신의 이름"으로 보인다. 영어 화면에서도 `한국어`, 중국어 화면에서도 `English`. 잘못 바꿔도 자기 언어를 찾아 돌아올 수 있게.
- 개발용 가짜 언어 `x-pseudo` **[제안]**: 영어 문구를 40% 늘리고 `⟦ ⟧` 로 감싸며 일부 글자를 2칸 문자로 바꾼다. 설정 목록에는 없고 `MASIL_LANG=x-pseudo` 로만 켠다. 번역 누락(감싸지지 않은 문구 = 코드에 박힌 문구)과 긴 문구로 인한 깨짐을 번역 전에 찾는 용도.

### 6.2 언어 결정 순서 (G3)

```
1. 환경변수 MASIL_LANG          (일회성 덮어쓰기, 시험·문제 해결용)
2. config.toml [ui] language     ("auto" 가 아니면 그 값)
3. 기존 사용자 보호              (아래 6.2.1 — 0.1.3 이하에서 쓰던 기기면 ko)
4. OS 언어                       LC_ALL > LC_MESSAGES > LANG
                                 → 셋 다 없거나 "C"/"POSIX" 면:
                                    macOS: AppleLanguages 첫 항목
                                    Windows: 사용자 UI 언어(GetUserPreferredUILanguages, x/sys)
5. 위에서 못 정하면 en
```

- OS 값 → 지원 언어 매핑 **[제안]** (`x/text/language` 의 BCP 47 해석·매칭 사용):
  - `ko*` → `ko`
  - `zh_CN`, `zh_SG`, `zh-Hans*`, 지역 없는 `zh` → `zh-Hans`
  - `zh_TW`, `zh_HK`, `zh_MO`, `zh-Hant*` → **`zh-Hans`** (번체 미지원. 영어보다 간체가 읽기 쉽다고 판단 — 오너 확인 필요)
  - 그 밖(`en*`, `ja`, `de` …) → `en`
- **설정 `language = "auto"` 가 기본값.** "auto" 는 실행할 때마다 다시 계산한다 — OS 언어를 바꾸면 따라간다. 사용자가 직접 고르면 그 값이 저장된다.
- macOS 의 AppleLanguages 는 `defaults read -g AppleLanguages` 실행 대신 설정 파일을 읽는 방식이든 명령 실행이든 **[빌더 재량]**, 단 시작 시간 +20ms 이내, 실패하면 조용히 다음 단계로.

#### 6.2.1 기존 사용자 보호 **[제안]**

한국 개발자 PC 는 `LANG=en_US.UTF-8` 인 경우가 많다. 그대로 4단계를 적용하면 0.1.4 로 업데이트하는 순간 한국어 사용자가 영어 화면을 본다(안티골).
- 0.1.4 첫 실행 때 **이미 `credentials.json` 이나 `state.json` 이 있는 기기**(= 0.1.3 이하를 쓰던 기기)이고 `language` 가 없거나 "auto" 이면 → `ko` 로 정하고 `state.json` 에 `language_legacy_default: "ko"` 를 남긴다. `config.toml` 은 건드리지 않는다(고장 난 config 보호 규칙, `client-architecture.md` 3.3).
- 그리고 한 번만 토스트: `언어: 한국어 · 설정 > 화면 > 언어에서 바꿀 수 있어요 (Language: Settings › Display)`.
- 사용자가 설정에서 언어를 직접 고르면 그 값이 우선하고 위 표시는 더 쓰지 않는다.

#### 6.2.2 데몬

자동 시작된 데몬(launchd·systemd·Windows 시작프로그램)은 셸 환경변수를 보지 않는다(README 의 `MASIL_SERVER` 경고와 같은 문제). 그래서 `LANG` 이 없을 수 있다.
- **[제안]** TUI 는 실행할 때마다 결정한 언어를 `state.json` 의 `resolved_language` 에 적는다. 데몬 순서: `config.toml` 의 명시 값 > `state.json` 의 `resolved_language` > OS 언어(4단계).
- 언어를 바꾸면 데몬은 다음 알림부터 새 언어로 띄운다(데몬은 알림을 띄울 때마다 설정을 다시 읽는 지금 구조를 따른다 **[빌더 재량]**).
- `masil daemon status` 에 `언어  English (config)` / `언어  한국어 (TUI 기록)` 처럼 어디서 왔는지 한 줄.

### 6.3 언어 바꾸기 — 사용자 흐름

원칙: **어느 언어 화면에서든 "language" 라는 영어 단어로 찾을 수 있다.** 명령 팔레트(`ctrl+k`)의 언어 명령은 지역화된 이름(`언어 바꾸기` / `Change language` / `切换语言`)과 함께 영어 별칭 `language`, `lang` 으로도 검색된다 **[제안]**.

**120×40 (표준 모드)**
1. `ctrl+k` → `lang` 입력 → `언어 바꾸기 (language)` 선택 → 설정 화면이 `화면` 장의 `언어` 줄에 포커스된 채 열린다. 또는 설정 → `화면` → `언어`.
2. 줄 모양: `언어   자동 (한국어)   한국어   English   简体中文` — `←/→` 로 고르면 **그 즉시** 모든 화면(상태줄·목록·대화창·도움말)이 새 언어로 다시 그려진다.
3. 토스트가 새 언어로: `Language: English`. `config.toml` 에 저장(`Save` 가 `ErrNotLoaded` 면 기존 규칙대로 이번 실행에만 적용 + 안내).
4. 입력창에 쓰던 글, 스크롤 위치, 선택한 메시지, 열린 스레드는 그대로(레이아웃 모드 전환과 같은 보존 규칙).

**80×24 (위젯 모드)**
- 설정은 전체 화면 목록. `언어` 줄은 한 값만 보이고 `‹ 简体中文 ›` 처럼 좌우로 돌린다. 나머지는 같다.

**초소형 (43칸 이하 등)**
- 설정 화면 대신 명령 팔레트로만 바꾼다(지금 초소형의 설정 진입 방식과 같게 **[빌더 재량]**). 팔레트에서 언어 세 개가 바로 목록으로 뜬다.

**첫 실행 (로그인·가입 화면)** **[제안]**
- 막는 선택 화면은 두지 않는다(첫 실행 마찰을 늘리지 않음). 6.2 로 정한 언어로 바로 로그인/가입 화면이 뜬다.
- 화면 아래 한 줄: `Language: English · <키> to change` — 누르면 세 언어를 돌린다. 키는 **[빌더 재량]**(기존 키맵과 겹치지 않을 것, 키맵 충돌 시험으로 확인).
- 120×40 에서는 한 줄 전체, 80×24 에서는 `EN · <키>`, 초소형에서는 표시 생략(팔레트로 가능).

**CLI**
- `masil help`, `masil login` 의 질문, `masil daemon status` 출력 등 CLI 출력도 같은 언어 결정을 따른다.
- 일회성: `MASIL_LANG=en masil daemon status`. 새 CLI 플래그·하위 명령은 만들지 않는다 **[제안]**.

### 6.4 카탈로그 설계 — 무엇으로 문구를 관리하나

용어: **카탈로그** = "문구 사전". 코드에는 문구 대신 키(예: `friends.request_from`)만 두고, 언어별 사전에서 실제 문장을 꺼낸다.

#### 6.4.1 두 후보 비교

| 기준 | A. `golang.org/x/text/message` (+ `gotext` 도구) | B. 작은 자체 카탈로그 (언어별 TOML → 생성된 Go 타입 함수) |
|---|---|---|
| 새 의존성 | 없음(이미 있는 x/text 모듈). 단 `gotext` 추출 도구가 필요 | 없음(TOML 은 이미 `BurntSushi/toml`, 생성기는 저장소 안 `go run`) |
| 키 오타 | 키가 문자열(보통 원문 문장 자체가 키) → **실행해야 발견** | 키가 Go 함수 → **컴파일 오류** |
| 인자 | `Printf` 식 `%s %d` — 개수·순서 실수는 `go vet` 일부만 잡음 | 이름 있는 인자 `{name}`, 타입 고정 함수 `FriendsRequestFrom(name string)` |
| 복수형 | 지원(CLDR 규칙, `plural.Selectf`) — 쓰기가 번거로움 | 필요한 것만: en `one/other`, ko·zh `other` 하나. 단순 |
| 한국어 조사(은/는) | 지원 없음 | 우리 규칙을 직접 넣을 수 있음(6.5) |
| 폭 예산(최대 칸 수) 검사 | 지원 없음 | 키마다 `max` 를 적고 생성기·시험이 언어별 폭 검사 |
| 번역 누락 검사 | 실행 시 원문으로 떨어짐(조용히 섞임) | 생성기가 언어별 누락을 목록으로, 출시 관문에서 실패 |
| 번역자 편의 | `gotext` 의 JSON 파일 | 언어별 TOML(사람이 읽고 diff 로 검토 쉬움) |
| 성숙도 | x/text 는 안정, `gotext` 는 사실상 실험 도구·문서 적음 | 우리가 유지보수(생성기 수백 줄) |

#### 6.4.2 결정 **[제안]: B — 작은 자체 카탈로그.** `x/text` 는 `language`(OS 언어 해석·매칭)만 쓴다.

이유: masil 은 "깨지면 안 되는 폭"이 최우선 품질 기준이라 **폭 예산 검사**가 꼭 필요하고, 0.1.3 과 병렬이라 **키 오타·인자 실수를 컴파일에서** 잡아야 사고가 줄고, 한국어 조사·D8 같은 우리만의 규칙을 넣어야 한다. 셋 다 A 로는 안 된다. 언어가 3개라 복수형 규칙은 손으로 써도 작다.

#### 6.4.3 카탈로그의 겉모양 (계약 수준)

- 새 core 패키지 `internal/i18n`. 의존: `textwidth`, `x/text/language` 만. `humanize`·`textwidth` 처럼 **어디서든 import 가능**(`client-architecture.md` 2.2 에 추가).
- 원본 파일: `internal/i18n/locales/<언어>/<영역>.toml` — 영역(area)은 기능 단위 파일. 예: `common.toml`, `auth.toml`, `chat.toml`, `feed.toml`, `fun.toml`, `settings.toml`, `shell.toml`, `help.toml`, `cli.toml`, `daemon.toml`, `errors.toml`, `alerts.toml`, `time.toml` — 그리고 0.1.3 영역 `tools.toml`(도구 허브·자격증명), `termpane.toml`, `lazygit.toml`, `leetcode.toml`, `workspace.toml`, `archcanvas.toml`, `apitest.toml`(`claude.toml` 은 만들지 않는다 — claude 관련 문구는 `workspace.toml`, v0.1.3 설계서 JX8). 영역을 파일로 나누는 이유는 0.1.3·0.1.4 가 같은 파일을 동시에 고치는 충돌을 줄이기 위해서다(10장).
- **한국어(`ko`)가 원본**이다 **[제안]**: 키와 인자, 설명(번역자용 맥락), 폭 예산은 ko 파일에 적는다. 제품이 한국어로 설계됐고 오너가 한국어로 검토하기 때문.
- 한 항목의 모양(예시, 정확한 문법은 **[빌더 재량]**):

  ```toml
  # locales/ko/chat.toml
  [members_count]
  desc   = "채널 헤더의 멤버 수"
  params = { n = "int" }
  max    = 10            # 이 문구가 들어갈 자리의 최대 칸 수(선택)
  other  = "멤버 {n}명"

  # locales/en/chat.toml
  [members_count]
  one    = "{n} member"
  other  = "{n} members"

  # locales/zh-Hans/chat.toml
  [members_count]
  other  = "{n} 位成员"
  ```

- 생성기(`go generate ./internal/i18n`, 저장소 안 도구)가 만드는 것: 영역별 타입 함수, 예 `t.Chat.MembersCount(n int) string`, `t.Friends.RequestFrom(name string) string`. 코드는 `ctx.T.Chat.MembersCount(3)` 처럼 부른다. 생성 파일은 커밋하고, CI 가 "생성기를 다시 돌렸을 때 diff 가 없음"을 확인한다.
- 생성기가 **실패로 막는 것**: ko 에 없는 키가 다른 언어에 있음 / 인자 이름 집합이 언어마다 다름 / 그 언어의 복수형 범주가 빠짐(en 은 `one`·`other` 둘 다) / 조사 표시가 ko 가 아닌 언어에 있음 / D8 위반(`{…} 님`) / 문구 안에 제어 문자·ANSI 이스케이프·양방향 제어 문자(U+202A~202E, U+2066~2069)·탭 / `max` 를 넘는 문구(ko·en·zh 각각 실제 폭으로 계산).
- 생성기가 **경고로 보고하는 것**(실패 아님, 개발 중 허용): en·zh 에 아직 없는 키(누락) — 실행 시 대체 순서로 보인다. 출시 관문에서는 실패(9장).
- 실행 시 대체 순서 **[제안]**: `zh-Hans → en → ko`, `en → ko`, `ko` 는 그 자체. 중국어 사용자는 한국어보다 영어를 읽을 가능성이 높다.
- 문구에는 스타일(색·굵게)을 넣지 않는다. 강조가 필요한 조각은 인자로 넘기고 스타일은 코드가 입힌다(예: `{key} 보내기` 의 `{key}` 에 테마 색을 입힌 `enter`). 이유: 번역자가 이스케이프를 다루지 않게, 그리고 언어마다 어순이 달라도 강조가 따라가게.
- **보안**: 문구는 컴파일 때 고정되고 사용자 입력은 언제나 인자로만 들어간다 — 사용자 글을 형식 문자열로 쓰는 일(`Sprintf(userText)`)이 구조적으로 없다. 인자로 들어가는 사용자 텍스트는 지금처럼 화면에 그리기 전에 `textwidth.Sanitize` 를 거치고, OS 알림은 `notify` 의 OS 백엔드 규칙(AppleScript·토스트 직접 호출, 문자열 끼워 넣기 없음)을 그대로 지난다. 번역 문구 자체도 위 생성기 검사로 제어 문자를 막는다.

#### 6.4.4 화면 코드가 카탈로그를 받는 법

- `ui.Context` 에 `T *i18n.T`(현재 언어의 사전)와 `Lang i18n.Locale` 을 더한다(`client-architecture.md` 5.3.2 수정). 모든 `View()` 가 `ctx.T` 로 문구를 꺼내므로, 언어를 바꾸면 루트 앱이 `ctx.T` 만 갈아 끼우고 다시 그리면 끝이다(재시작 없음).
- 화면 밖(CLI, 데몬, `notify`, `api` 의 오류 설명)은 `i18n.For(locale)` 로 사전을 받는다.
- `internal/api/describe.go` 의 오류 코드 → 한국어 표(47줄)는 `errors.toml` 로 옮기고, `api` 는 코드·세부 정보만 돌려준다(`api` 가 UI 언어를 몰라도 되게).
- 키맵 도움말(`?`)의 동작 설명, 명령 팔레트의 명령 이름, 슬래시 명령 `Catalog()` 의 사용법·설명, `slash.Parse` 의 오류 문구 모두 카탈로그로. 명령 이름(`/poll`)과 키 이름(`ctrl+k`)은 번역하지 않는다.
- 명령 팔레트 검색 **[제안]**: 지역화된 이름 + 영어 이름 둘 다로 퍼지 검색. 중국어·한국어 화면에서도 영어로 찾을 수 있다.

### 6.5 한국어 조사, '님', 그리고 다른 언어로의 대응

한국어는 앞 낱말의 받침에 따라 조사가 바뀐다(민준**이** / 하나**가**). 영어·중국어에는 이런 것이 없다.

**규칙 1 — D8 '님'을 쓰면 조사 문제가 사라진다.** '님'은 받침(ㅁ)이 있으므로 뒤 조사는 언제나 `이/은/을/과` 로 고정이다. 그래서 사람 이름이 들어가는 한국어 문구는 **`{name}님` + 고정 조사**를 기본으로 쓴다: `{name}님이 팔로우했어요`, `{name}님의 친구 요청`. 지금 서버·클라이언트 문구가 이미 이렇게 되어 있다.

**규칙 2 — 사람 이름이 아닌 것(방 이름, 채널 이름, 숫자 등)에 조사가 붙어야 하면 조사 표시를 쓴다:** `{space|은/는}`, `{n|이/가}`, `{name|을/를}`, `{x|과/와}`, `{x|으로/로}`.
- 마지막 글자가 한글 음절이면 받침으로 정확히 고른다(`으로/로` 는 ㄹ 받침 예외까지).
- 마지막 글자가 숫자면 한국어 읽기로 고른다(1·3·6·7·8·0 은 받침 있음: 일·삼·육·칠·팔·영, 2·4·5·9 는 없음: 이·사·오·구). `{n|개}` 같은 단위가 붙으면 단위 기준.
- 그 밖(영문 등)은 **괄호 병기 `이(가)`, `은(는)`, `을(를)`** **[제안]**. 영문 이름의 발음으로 받침을 추정하면 틀리기 쉽다(Mike vs Sam). 대신 문구를 쓸 때 가능하면 조사가 필요 없는 어순으로 쓴다: `노바 개발방에 초대했어요`(에는 받침과 무관), `#개발 · 새 메시지`.
- 조사 표시는 **ko 파일에서만** 쓸 수 있다(생성기가 다른 언어에서 막음).

**규칙 3 — 다른 언어로 옮길 때 '님'은 없앤다.** 영어는 이름만(`sam followed you`), 중국어도 이름만(`sam 关注了你`). 존칭 대응어(Mr., 先生)는 쓰지 않는다 **[제안]** — SNS 말투에 맞지 않고 성별을 가정한다.

**규칙 4 — 영어·중국어에서 신경 쓸 것.**
- 영어: 복수형(`1 reply` / `2 replies`), 소유격(`sam's guestbook`), 문장형 대문자(Sentence case: `Friend requests`, Title Case 아님). 대명사로 성별을 가정하지 않는다(`they` 나 이름).
- 중국어: 복수형 없음(`other` 하나), 양사(`3 条消息`, `5 位成员`)는 문구 안에 직접 쓴다. 숫자와 한자 사이 공백은 넣지 않는 쪽이 기본(`3条消息`) — 최종은 원어민 검수 **[빌더 재량 → 검수자]**.
- 어순이 언어마다 다르므로 인자는 이름으로만 부르고 순서에 기대지 않는다(`{actor}님이 {space} 방에 초대했어요` / `{actor} invited you to {space}` / `{actor} 邀请你加入 {space}`).

**말투 [제안]**
- ko: 지금처럼 해요체("~했어요", "~할 수 없어요").
- en: 짧고 친근하게, 문장형 대문자, 버튼·라벨에는 마침표 없음.
- zh-Hans: 간결하게, 상대를 `你` 로(SNS 말투, `您` 은 딱딱함 — 오너 확인 필요), 문장에는 전각 문장부호(`，。：`), 라벨 끝 문장부호 없음.

### 6.6 폭과 자르기 — 특히 좁은 모드

같은 뜻이라도 언어마다 칸 수가 다르다:

| 뜻 | ko | en | zh-Hans |
|---|---|---|---|
| 알림 | `알림` 4칸 | `Notifications` 13칸 | `通知` 4칸 |
| 친구 요청 | `친구 요청` 9칸 | `Friend requests` 15칸 | `好友请求` 8칸 |
| 3분(전) | `3분` 3칸 | `3m` 2칸 | `3分钟` 5칸 |
| 지휘소 모드 | `지휘소` 6칸 | `Command` 7칸 | `指挥台` 6칸 |

대체로 **영어가 가장 길고**, 중국어는 한국어와 비슷하거나 짧다. 그러나 중국어 전각 문장부호(`，：（`)는 2칸이라 짧은 라벨에서 예상보다 길어진다.

규칙 **[제안]**:
1. **폭 예산**: 좁은 자리(초소형·위젯 탭, 상태줄 모드 이름·단축키 힌트, 버튼, 표 머리, 설정 줄 이름, 시간 표기)에 들어가는 키는 `max`(최대 칸 수)를 적는다. 생성기가 세 언어 모두 실제 폭(`textwidth.Width`, 즉 `x/ansi`)으로 검사해 넘으면 실패.
2. **짧은 형**: 공간이 모자라는 자리용으로 `short` 변형을 둘 수 있다: `Notifications` / short `Alerts`. 화면 코드는 모드·남은 폭에 따라 고른다(위젯·초소형 = short 우선).
3. **그래도 넘치면 자른다**: 기존 `textwidth.Truncate`(그래핌 단위, `…` 꼬리) 그대로. 2칸 글자 경계에서 1칸이 남으면 공백으로 채운다(이미 있는 규칙). 단어 중간이 잘린 영어보다 짧은 형이 낫다 — 짧은 형이 먼저.
4. **잘리면 안 되는 문구**: 보안 경고(0.1.3 의 Claude 키보드 넘기기 경고, 작업공간 공유 경고 등), 확인 대화상자의 "무엇을 하는지" 문장, 오류의 핵심 문장은 **자르지 않는다**. 들어가지 않으면 줄바꿈하고, 그래도 안 들어가면 대화상자가 스크롤되거나 "창을 키워 주세요" 를 보인다. 카탈로그에 `no_truncate = true` 로 표시하고 시험이 모든 필수 크기에서 전문이 보이는지 확인.
5. **줄바꿈**: `textwidth.Wrap` 은 이미 한자·한글 사이에서 끊고 닫는 문장부호 앞(`，。！？：；）」`)에서는 끊지 않는다. 중국어 문단은 띄어쓰기가 없어도 바르게 감긴다 — 언어별 시험을 추가해 이를 고정.
6. **표 정렬**: 열 너비는 고정 숫자가 아니라 "그 열에 들어갈 문구들 중 가장 넓은 것"으로 계산한다(언어마다 다르므로). 지금 고정 폭을 쓰는 곳이 있으면 이관 때 고친다.
7. 모호 폭 문자(`·`, `…`, `—`)는 지금처럼 1칸으로 본다. 중국어 문구에서 가운뎃점은 `·` 를 그대로 쓰고 전각 `・` 를 쓰지 않는다(검수 지침에 적음).

### 6.7 날짜·시각·숫자 (G4)

`internal/humanize` 는 지금 한국어 전용이다(`client-architecture.md` 4.9). 함수마다 언어를 받도록 바꾼다(예: `humanize.For(lang).MessageTime(now, t, loc)` — 모양은 **[빌더 재량]**). 시간대(`ctx.Loc`)는 지금처럼 OS 를 따르고 언어와 무관. 12/24시간은 지금처럼 `[ui] clock` 설정을 따르고 언어가 바꾸지 않는다 **[제안]**.

| 함수 | ko (지금 그대로) | en | zh-Hans |
|---|---|---|---|
| Clock 24h / 12h | `11:05` / `오전 11:05` | `11:05` / `11:05 AM` | `11:05` / `上午11:05` |
| MessageTime 오늘 | `11:05` | `11:05` | `11:05` |
| 어제 | `어제 11:05` | `Yesterday 11:05` | `昨天 11:05` |
| 올해 | `11월 3일 11:05` | `Nov 3, 11:05` | `11月3日 11:05` |
| 그 이전 | `2025. 11. 3.` | `Nov 3, 2025` | `2025/11/3` |
| Relative | `방금` `3분` `2시간` `어제` `11월 3일` | `now` `3m` `2h` `Yesterday` `Nov 3` | `刚刚` `3分钟` `2小时` `昨天` `11月3日` |
| Count | `999` `1.2천` `3.4만` `1.2억` | `999` `1.2K` `3.4M` `1.2B` | `999` `9999` `1.2万` `1.2亿` (만 단위부터) |
| Duration | `45초` `25분` `1시간 30분` | `45s` `25m` `1h 30m` | `45秒` `25分钟` `1小时30分钟` |
| DayDivider | `2026년 11월 5일 목요일` | `Thursday, November 5, 2026` | `2026年11月5日 星期四` |

- 영어 월 이름은 짧은 형(`Nov`)으로 고정(폭 예산). 요일 전체 이름은 DayDivider 에만.
- Relative 는 모든 언어에서 **8칸 이하**(지금 한국어 최대 `11월 3일` 과 같음) — 시험으로 고정. 중국어 `3分钟` 이 좁은 모드에서 넘치면 `short` 로 `3分`.
- 표기 근거는 CLDR(유니코드 공용 지역 자료)의 각 언어 기본 형식을 따르되, 표의 값이 최종이다. 표 밖의 형식은 원어민 검수 **[빌더 재량 → 검수자]**.
- 천 단위 쉼표 `1,234` 는 세 언어 공통(지금 쓰는 곳이 있다면).

### 6.8 화면 밖에서 보이는 문구

- OS 데스크톱 알림: 데몬·TUI 모두 7장의 `template` 을 카탈로그로 렌더. 알림을 띄우는 앱 이름(macOS "스크립트 편집기"/"Script Editor")은 OS 가 정하므로 우리가 바꾸지 않는다.
- `masil daemon status` 등 CLI 출력, 대화형 질문(`masil login` 의 "아이디:" 등): 카탈로그.
- 최근 경고(`masil daemon status` 의 로그 줄): 로그는 번역하지 않으므로 그대로 보인다(논골). 0.1.4 이후 새로 쓰는 로그 문구는 영어.

### 7.2 결정 **[제안]: 클라이언트가 구조화 데이터로 렌더하고, 서버는 "대체 문구"만 연결 언어로 만든다**

두 후보:
- (가) 서버 쪽 지역화 — 서버가 사용자 언어(설정 또는 `Accept-Language`)를 보고 문장을 만들어 보냄.
- (나) 클라이언트 쪽 렌더 — 서버는 "무슨 종류의 알림인지 + 인자"만 보내고 클라이언트가 카탈로그로 문장을 만듦.

(나)를 기본으로 한다. 이유:
1. 이미 오류·시스템 메시지·알림함이 (나) 방식이다. 하나로 통일된다.
2. 한 사용자가 기기마다 다른 언어를 쓸 수 있다(회사 PC 영어, 집 PC 한국어). alert 는 **한 번 만들어 로그에 저장하고 여러 기기에 재전송**되므로, 서버가 하나의 언어로 굳혀 저장하면 다른 기기에서 틀린 언어가 된다.
3. 번역을 고칠 때 서버 배포 없이 클라이언트만 고치면 된다(배포는 오너 승인 사항이라 번거롭다).
4. 서버가 사용자 언어를 저장하지 않아도 된다(개인정보 최소화).

그러나 (나)만으로는 두 경우가 빈다: **0.1.3 이하 옛 클라이언트**(template 을 모름 → `title` 을 그대로 띄움)와, **새 서버가 보낸, 이 클라이언트가 아직 모르는 template**(앞으로의 기능). 그래서 `title`/`body` 는 "대체 문구"로 남기고, 서버가 **그 연결·요청이 밝힌 언어**로 만든다. 언어를 밝히지 않은 연결(옛 클라이언트)은 한국어 — 지금과 똑같다.

### 7.3 계약 변경 (더하기만)

**요청 헤더** — `api.md` 0.1 에 추가:
- 클라이언트는 모든 REST 요청과 WebSocket 연결 요청(`GET /v1/ws`, 데몬 notify 연결 포함)에 `Accept-Language: <ko|en|zh-Hans>` 를 보낸다(현재 결정된 언어 하나). 서버는 이 셋 중 하나가 아니면 `ko` 로 본다. 언어를 바꾸면 클라이언트는 다음 요청부터 새 값을 보내고, 소켓은 다음 재접속부터 적용된다(대체 문구에만 영향이므로 즉시 재접속할 필요 없음 **[제안]**).
- 서버는 이 값을 **저장하지 않는다.** 그 요청 처리 중, 또는 그 소켓 연결의 메모리 안에서만 쓴다(예외: 7.4 기본 채널 이름은 결과물이 데이터로 남음).

**`Alert` 에 필드 추가** — `api.md` 2장, `events.md` 4.7:

```ts
interface Alert {
  // … 기존 필드 그대로 …
  title: string;               // 대체 문구: 이 연결/요청의 Accept-Language 로 렌더(없으면 ko). <= 80 code points
  body: string;                // 대체 문구, 같은 규칙. <= 200 code points
  template: AlertTemplate | null;   // NEW. null = 옛 서버가 저장한 alert(대체 문구만 있음)
}
interface AlertTemplate {
  id: AlertTemplateId;              // 예: "social.follow", "social.follow_request", "invite.space", "focus.summary"
  params: Record<string, string | number>;  // 예: { actor: "하나", space: "노바 개발방" } / { mention: 3, dm: 2, … }
}
```

- `template.id` 목록과 각 id 의 인자 이름은 **한 파일에 고정** **[제안]**: `docs/contract/i18n/alert-templates.json`. 서버 시험과 Go 시험이 **둘 다 이 파일을 읽어** 자기 쪽 카탈로그가 모든 id·인자를 갖는지 확인한다(언어가 다른 두 코드가 같은 목록을 보도록 — 지금 Go 시험이 README·워크플로우 YAML 을 읽는 것과 같은 방식).
- 메시지 알림(`sam · 노바 개발방 #개발`)은 이름·방·채널 조합이라 대부분 언어 중립이지만, 일관성을 위해 `message.channel` / `message.dm` / `message.group` 템플릿으로 보낸다(인자: `actor`, `space`, `channel`, `group`). `body` 는 메시지 본문(사용자 글)이라 번역하지 않는다 — `template.params` 에 넣지 않고 `body` 그대로 쓴다.
- 클라이언트 렌더 규칙: `template` 이 있고 그 `id` 를 알면 카탈로그로 렌더, 아니면 `title`/`body` 를 그대로. 인자 값(사람 이름·방 이름)은 사용자 데이터이므로 `Sanitize` 를 거친다.
- 집중 모드 요약: `template = { id: "focus.summary", params: counts }`. 클라이언트는 이미 `FocusSummary.counts` 가 있으니 그대로 렌더.

**서버 구현의 모양** (계약 수준, 세부는 **[빌더 재량]**):
- 서버에 작은 문구 표 `server/src/lib/i18n.ts`(템플릿 id × ko/en/zh-Hans, 약 20줄 × 3). 서버 코드 다른 곳에는 사용자용 한국어 문자열을 두지 않는다 — 서버에도 "한글 문자열 박기 금지" 검사(주석·`validate.ts` 정규식·이 파일 제외).
- UserHub 로그(재전송용)에는 `template` 과 함께 저장하고, **보낼 때** 연결의 언어로 `title`/`body` 를 렌더한다. 이미 저장된 옛 alert(템플릿 없음)는 저장된 한국어 문구 그대로.
- `DELETE /v1/me/focus` 의 `FocusSummary.items` 처럼 REST 로 alert 를 돌려주는 곳과 `focus.ended` 이벤트의 요약도 그 요청의 `Accept-Language` 로 대체 문구 렌더.

### 7.4 기본 채널 이름 **[제안]**

방을 만들 때 생기는 기본 채널은 **만든 사람의 요청 언어**로 이름 짓는다: ko `일반`, en `general`, zh-Hans `综合`(후보 `常规`, 검수자 결정). 한 번 만들어지면 사용자 데이터라 언어를 바꿔도 이름이 바뀌지 않는다(방장이 이름을 바꿀 수 있다). 기존 방은 그대로.

### 7.5 채널 이름 규칙에 한자 허용 **[제안]**

`^[a-z0-9가-힣_-]{1,32}$` 로는 중국어 사용자가 채널을 중국어로 지을 수 없다. → `가-힣` 에 **CJK 통합 한자 기본 블록(U+4E00–U+9FFF)과 확장 A(U+3400–U+4DBF)** 를 더한다. `api.md` 0.3, `server/src/lib/validate.ts`, 클라이언트 쪽 같은 검사를 함께 고친다. 위험: 비슷하게 생긴 한자로 다른 채널을 흉내 내기 — 채널은 방 안에서만 보이고 방장이 관리하므로 낮다고 판단. handle(아이디) 규칙 `^[a-z0-9_]{3,20}$` 은 그대로 둔다(멘션·주소에 쓰이므로 ASCII 유지).

### 7.6 0.1.3 서버 기능의 규칙 (첫날부터)

0.1.3 다섯 기능(LeetCode·Claude Code 공유·코드 작업공간·아키텍처 캔버스·API 시험 도구)이 서버에서 사용자용 문구를 만들 일이 생기면(공유 초대 알림, "sam님이 Claude 세션을 공유했어요" 같은 시스템 메시지, 오늘의 문제 알림 등):
- **완성된 한국어 문장을 서버에서 만들지 않는다.** 알림은 새 `template.id`(`alert-templates.json` 에 추가) + 인자, 시스템 메시지는 새 `SystemEvent.event` 종류, 오류는 기존 `code` 체계.
- 0.1.3 이 0.1.4 보다 먼저 출시되더라도 이 규칙은 같다(0.1.3 클라이언트는 한국어만 렌더할 뿐).

| x/text/language 로 바이너리 크기 증가 | 낮음 | 수백 KB 수준 예상 — 빌더가 측정해 1MB 넘으면 손으로 쓴 간단 해석기로 대체 **[빌더 재량]** |

### 11.1 약관·법적 메모

- masil 앱 안에 약관 원문은 없다(설정의 "개인정보"는 계정 공개 범위 설정). 약관·개인정보 처리 방침을 새로 만든다면 그 번역은 법적 효력 문제가 있어 "어느 언어판이 우선인지"를 함께 정해야 한다 — 이번 범위 아님, 오너 메모로만 남긴다.
- 번역자에게 받은 번역문의 저작권: 저장소가 MIT 이므로 기여 번역도 MIT 로 받는다는 문구를 기여 안내(또는 PR 템플릿)에 한 줄 두는 것을 제안 **[제안]**.
- 중국어 지원은 "중국어로 읽을 수 있음"이지 중국 본토 서비스 제공 선언이 아니다. 본토 사용자 대상 운영(현지 규제·실명제 등)은 하지 않는다 — README 에 따로 적지는 않는다 **[제안]**.
- 0.1.3 의 LeetCode·Claude 관련 약관 위험은 그 설계서의 몫이다. 다만 경고 문구의 번역은 원문과 뜻이 같아야 하므로 9.5 의 `legal = true` 검수 대상이다.

## 13. 오너가 확인할 수 있는 수락 기준

설치·실행은 개발 빌드로 해도 된다(로컬 개발 절차는 README). 각 항목은 손으로 해 볼 수 있다.

**언어 결정**
1. 새 설정 폴더(`MASIL_CONFIG_DIR=$(mktemp -d)`)로 `LANG=en_US.UTF-8 masil` → 로그인 화면이 영어. `LANG=zh_CN.UTF-8` → 간체 중국어. `LANG=ko_KR.UTF-8` → 한국어. `LANG=de_DE.UTF-8` → 영어. `LANG=zh_TW.UTF-8` → 간체 중국어.
2. 0.1.3 을 쓰던 설정 폴더 그대로 `LANG=en_US.UTF-8 masil` → **한국어**로 뜨고, 언어 안내 토스트가 한 번만 나온다(두 번째 실행부터는 없음).
3. `MASIL_LANG=en masil daemon status` → 영어 출력. 그냥 `masil daemon status` → 설정 언어로, `언어` 줄에 출처 표시.

**바꾸기**
4. 120×40 에서 채널 대화 중 입력창에 글을 쓰다가 `ctrl+k` → `lang` → 영어 선택 → 화면 전체가 즉시 영어, 입력 중이던 글·스크롤 위치·열린 스레드 그대로. 다시 한국어로 돌아와도 같다.

12. 0.1.3 클라이언트로 같은 서버에 붙으면 알림이 지금처럼 한국어로 뜬다(옛 클라이언트 호환).

## 15. 빌더 질문에 대한 결정 (내 판단, 2026-11-09)

빌더가 계획을 세우며 물은 것에 대한 답이다. 모두 **[내 판단]** 이고 오너가 뒤집을 수 있다. v0.1.3 설계서(`2026-11-09-masil-v0.1.3-design.md`) 3장과 5장 JX10 이 이 결정을 따른다.

1. **12장의 [제안] 은 계획에서 확정으로 다룬다.** 12장 1~25번과 본문의 모든 **[제안]** 은 계획서·작업 목록을 짤 때 정해진 것으로 본다. 오너는 언제든 고칠 수 있고, 고치면 그 항목에 걸린 작업만 다시 짠다.
2. **"한국어 골든 무변화" 불변식은 문구 이관 PR 에만 적용한다.** 9.1 의 "이관 PR 은 한국어 골든을 하나도 바꾸면 안 된다"는 기존 리터럴을 카탈로그로 옮기는 PR 의 규칙이다. 새 다국어 화면을 더하는 PR — 설정의 언어 줄, 로그인 화면 아래 언어 줄, 명령 팔레트의 언어 명령, `masil daemon status` 의 언어 줄, 기존 사용자용 한 번 안내 토스트 — 은 한국어 골든을 바꿀 수 있다. 그 PR 은 바뀐 골든을 하나하나 PR 설명에 적고 오너가 본다. 1.1·1.4 와 수락 기준 10번의 "한국어 화면은 한 글자도 바뀌지 않는다"도 이 범위로 읽는다.
3. **출시 순서는 0.1.3 다음 0.1.4.** 0.1.4 는 0.1.3 의 새 문구 전부(`tools`·`termpane`·`leetcode`·`lazygit`·`workspace`·`archcanvas`·`apitest` 영역)의 en·zh-Hans 를 담는다 — 9.4 출시 관문의 "누락 0·검수 100%"에 0.1.3 문구도 들어간다. 0.1.3 이 늦어지면 0.1.4 작업은 자기 브랜치에서 계속하고, 출시는 0.1.3 뒤에 한다(0.1.4 를 먼저 내지 않는다). 그래서 10.3 의 "0.1.3 이 먼저 출시될 때" 규칙은 언제나 적용된다.
4. **F0 에 "열린 언어" 관문을 넣는다.** 언어마다 열림/닫힘을 둔다(0.1.3 은 ko 만 열림, 0.1.4 에서는 9.4 출시 관문을 통과한 언어만 열림 — 11장 첫 위험의 "언어별로 따로 열기" 장치). 6.2 의 결정 순서가 닫힌 언어를 고르면 화면은 en 으로 대체해 보이고, 닫힌 언어는 설정의 언어 목록에서 숨긴다. `Accept-Language` 는 실제로 화면에 쓰는 언어(대체가 끝난 실효 언어)를 보낸다. 덧붙여 정한 것: en 자체가 닫혀 있으면 대체는 ko 로 간다 — 0.1.3 이 이 경우라 화면은 ko, `Accept-Language: ko` 다(10.3 과 같음). 개발·검수용 `MASIL_LANG` 은 관문을 건너뛴다(10.3 유지).
5. **서버 alert 템플릿 기반은 F0 에 넣는다.** `Alert.template` 필드, `docs/contract/i18n/alert-templates.json`, `server/src/lib/i18n.ts`, 계약 문서 문구(api.md 0.1·2장, events.md 4.7)를 F0 에서 한다. 그래서 0.1.3 서버 기능(작업공간 초대·주의 알림, 문서 댓글 멘션 등)은 첫날부터 template id 를 쓴다. 10.1 그림에서 "0.1.4 이관 PR 들"에 있던 "서버 alert template" 은 F0 로 옮긴다(채널 이름 규칙·기본 채널 이름은 0.1.4 그대로). 이 서버 변경의 배포는 0.1.3 출시와 함께 나가고, 배포는 그때 오너 승인이 필요하다.
