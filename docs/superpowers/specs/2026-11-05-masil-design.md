- 작성일: 2026-11-05

## 1. 의도 — 왜 만드는가

업무 중 슬랙·카카오톡 창으로 왔다 갔다 하는 게 귀찮다. **이미 열려 있는 터미널 안에서** 친구·동료와 채팅하고, 가볍게 SNS도 하고 싶다. 업무 도구만일 필요는 없다 — Threads/인스타/페북 같은 SNS 재미도 있으면 좋다. **[오너 결정]**

이름 `masil`(마실: 이웃집에 놀러 가 수다 떠는 것)은 **[내 결정]**. CLI 명령도 `masil`.

### 성공의 모습
- 터미널에서 `masil` 한 번 치면 슬랙급 채팅(방·채널·스레드)과 SNS 피드를 오가며 쓸 수 있다.
- **TUI가 "짱짱 이쁘다"** — 이 제품의 가장 중요한 품질 기준. 창 크기를 바꾸면 레이아웃이 즉시·자연스럽게 따라온다. **[오너 결정]**
- 다른 창에서 일하다가도 멘션/DM을 놓치지 않는다.

### 안티골 (기술적으로 돌아가도 실패인 것)
- 못생기거나, 리사이즈 시 깨지거나 겹치는 화면.
- 한글이 깨지거나 폭 계산이 틀려 테두리가 어긋나는 것 (한글·이모지는 폭 2칸).
- 메시지가 실시간으로 오지 않고 새로고침해야 보이는 것.
- 아무나 DM 폭탄을 보낼 수 있는 구조.

### 논골 (이번 범위 아님)
- 깃 연동 — 오너가 lazygit을 쓰므로 불필요. **[오너 결정]**
- 웹/모바일 클라이언트, 음성·영상 통화, 종단간 암호화, 결제. **[내 결정]**
- 이메일 인증·비밀번호 재설정 메일 (추후). **[내 결정]**

## 2. 사용자와 관계 구조

- **가입: 누구나** 터미널에서 바로 가입. **[오너 결정]** 수단은 아이디(handle)+비밀번호. **[내 결정]**
- **친구**: 친구 요청 → 수락 시 서로 1:1 DM 가능. **[오너 결정: "채팅은 우선 친구끼리"]**
- **DM 허용 규칙** **[내 결정]**: 상대가 (a) 친구이거나 (b) 같은 방 멤버이면 DM 가능(슬랙처럼). 모르는 사람은 불가. 사용자 설정으로 "친구만"으로 좁힐 수 있음.
  - 그룹 DM(최대 10명): 만든 사람이 모든 참여자에게 DM 가능해야 함.
  - 친구 끊기/방 탈퇴로 조건이 사라지면: 기존 대화는 읽기 전용으로 남음. 차단하면: 차단당한 쪽은 새 메시지·멘션 불가, 차단한 쪽 화면에서 해당 사용자 대화·글 숨김.
- **방(Space)** = 디스코드 서버 / 슬랙 워크스페이스 같은 "확장된 단톡". **[오너 결정]**
  - 누구나 방을 만들 수 있고, 방 안에 채널(`#일반`, `#잡담` …)을 판다.
  - 입장은 **초대 링크(코드)** — 만료 시간·최대 사용 횟수 설정 가능. 친구를 직접 초대할 수도 있다. **[오너 결정: 초대 링크]**
  - 권한 3단계: 방장(owner) / 관리자(admin: 채널 생성·삭제, 강퇴, 고정, 초대 관리) / 멤버. **[내 결정]**
  - 비공개 채널(초대된 멤버만)도 지원. **[내 결정]**
- **SNS 피드는 공개 공간**: 누구 글이든 볼 수 있고, 팔로우한 사람 글이 내 타임라인에 모인다. 계정 비공개(승인한 팔로워만) 옵션. **[내 결정]**
- **안전장치** **[내 결정]**: 사용자 차단, 신고, 요청 속도 제한(가입·로그인·글쓰기·업로드).
  - **전역 운영자(admin) 역할**을 첫 출시부터 둔다: 신고 목록 보기, 게시물/이미지 강제 삭제, 계정 정지. 전용 UI는 최소한(`masil admin …` 명령 또는 TUI 숨김 화면)이면 충분. 공개 가입·공개 이미지라 불법 콘텐츠 대응 수단이 반드시 필요하기 때문.

## 3. 기능 범위

### 3.1 채팅 (슬랙/디코식) — 핵심
- 채널 메시지, DM, 그룹 DM
- **스레드**: 아무 메시지에 답글 → 오른쪽 스레드 패널에서 이어서 대화. "답글 N개" 표시. **[오너 결정]**
- 이모지 리액션, @멘션(@handle, @here), 메시지 수정/삭제(본인; 관리자는 삭제 가능)
- 안 읽은 수 배지, 멘션 배지, 입력 중 표시, 접속 상태(온라인/자리비움/방해금지/오프라인)
- 마크다운 일부(굵게·기울임·인라인 코드·코드 블록·링크) 렌더 + 코드 블록 문법 강조
- 메시지 고정, 채널 내 검색 + 전역 검색(내가 접근 가능한 범위)
- 무한 스크롤로 과거 메시지 불러오기(커서 기반 페이지네이션)
- 오프라인이었다가 다시 켜면 놓친 메시지가 채워짐

### 3.2 SNS
- **피드(Threads/트위터식)**: 짧은 글(최대 500자), 답글(트리), 좋아요, 리포스트, 인용
- **사진 글(인스타식)**: 이미지 첨부(최대 4장, 장당 5MB). 터미널에선 하프블록(▀) 컬러 문자로 렌더. kitty/iTerm2 그래픽 프로토콜 지원 터미널에선 실제 이미지로 표시(가능하면). **[내 결정]**
- **스토리**: 24시간 뒤 사라지는 짧은 글/사진. 피드 상단에 링으로 표시. **[내 결정]**
- 팔로우/팔로워, 프로필(이름·소개·상태 메시지·아바타·방명록)
- 해시태그(#태그 클릭→태그 피드), 실시간 트렌드 태그 Top 10
- 타임라인 2종: 팔로잉 / 전체(발견)
- 알림함: 좋아요·답글·멘션·팔로우·친구요청·방 초대

### 3.3 재미·편의 기능 ("와다다다" 요청분) **[내 결정 — 오너가 빼거나 더할 수 있음]**
- **투표**: 채팅·피드 어디서든 `/poll` 로 생성, 막대그래프로 결과 표시
- **방명록**: 프로필에 싸이월드식 방명록
- **상태 메시지 + 현재 하는 일**: "🎧 듣는 중…", "🔨 배포 중" 같은 커스텀 상태
- **집중 모드**: 정해진 시간 동안 알림 끄기(방해금지), 끝나면 놓친 것 요약
- **슬래시 명령**: `/me`, `/shrug`, `/poll`, `/status`, `/focus 25m`, `/roll 2d6`, `/invite`
- **데스크톱 알림 — masil이 꺼져 있어도 받는다** **[오너 결정]**: 멘션·DM·방 초대 시 OS 알림. 집중 모드면 보류 후 요약.
  - 가벼운 백그라운드 데몬(`masil daemon`)이 서버와 소켓을 유지하며 알림만 담당. `masil daemon install/uninstall` 로 OS 자동 시작 등록(macOS launchd 사용자 에이전트, Linux systemd --user, Windows 시작프로그램). **[내 결정]**
  - TUI가 떠 있을 때는 TUI가 알림을 맡고 데몬은 쉬어 중복 알림이 없어야 한다. 데몬↔TUI 조율 방식(로컬 소켓/락 파일 등)은 **[빌더 재량]**.
  - 데몬은 세션 토큰을 TUI와 공유(`~/.config/masil/`), CPU·메모리 사용 최소. 모바일 푸시는 범위 밖.
- **명령 팔레트**: `ctrl+k` 로 방·채널·사람·명령 퍼지 검색 이동

## 4. TUI 디자인 — 최우선 품질 기준

- 참고: awesome-tuis 목록의 잘 만든 TUI들, Bubble Tea 생태계(Charm) 감성. **[오너 결정]**
- **테마 4종 모두 탑재**, 설정/명령으로 즉시 전환. 기본값은 **D. 레트로 앰버**. **[오너 결정]** (시안: `.superpowers/brainstorm/` 의 `visual-style.html`)
  - A. Charm 보라 — 둥근 테두리, 보라·핑크
  - B. 미드나잇 블루 — 각진 얇은 선, 파랑·주황
  - C. 크림 파스텔 — 밝은 바탕, 따뜻한 색(라이트)
  - D. 레트로 앰버 — 이중선 테두리, 노랑·빨강 (gruvbox 계열)
- **창 크기별 4가지 모드** — 단순히 패널을 접는 게 아니라, 모니터를 나눠 쓰는 방식마다 **다른 UX**를 준다. **[오너 결정: 전체/반쪽/1/4 상자/1/4 세로띠 구분]** 각 모드의 구성은 **[내 결정]** (시안: `layouts.html`). 터미널 칸 수로 자동 전환하고, 단축키로 고정도 가능.
  1. **지휘소 모드 — 모니터 전체** (약 200칸↑ × 50줄↑): `[방 레일] [채널·DM 목록] [대화창] [피드] [스레드 + 알림 세로 스택]`. 채팅과 SNS 피드를 **동시에** 본다.
  2. **표준 모드 — 반쪽(너비 1/2)** (약 100~200칸 × 40줄↑): `[채널·DM 목록(방 선택은 드롭다운)] [대화창]`, 스레드는 대화창 아래 분할로 열림. 피드는 `f`로 대화창 자리와 교체.
  3. **컴팩트 모드 — 1/4 상자(너비·높이 1/2)** (약 100~200칸 × 40줄↓): 목록 숨김, 상단 탭(열어 둔 채널·DM·피드·알림) + `ctrl+k` 이동. 메시지는 한 줄 요약형(시간·이름·본문)으로 빽빽하게. 스레드는 `enter`로 전체 교체.
  4. **위젯 모드 — 1/4 세로띠(너비 1/4)** (약 100칸↓, 세로로 김): 에디터 옆에 붙여 두는 메신저 위젯. 상단 탭 `채팅/피드/알림`, 말풍선을 세로로 쌓는 카톡풍(내 메시지 오른쪽 정렬).
  - 80×24 미만의 더 작은 창은 위젯 모드를 한층 더 축약. 정확한 중단점 수치는 **[빌더 재량]**, 단 **어떤 크기에서도 테두리·텍스트가 겹치거나 잘려 깨지면 안 되고**, 모드 전환 중에도 입력 중이던 글·스크롤 위치·선택 상태가 유지되어야 한다.
- 하단 상태줄: 현재 모드·단축키 힌트·접속 상태. 레일/탭의 "홈" = DM·친구·피드.
- 한글·이모지 폭 계산 정확(east-asian width), 한글 IME 입력이 자연스러울 것.
- 키보드 중심(vim풍 j/k + 화살표 둘 다), 마우스 클릭·스크롤도 지원.
- 부드러운 느낌: 로딩 스피너, 새 메시지 하이라이트 페이드 등 절제된 모션.

## 5. 기술 구성

### 5.1 클라이언트 **[내 결정]**
- Go + Charm 스택(Bubble Tea, Lip Gloss, Bubbles, Glamour/Chroma 등). 단일 바이너리.
- 배포: GitHub Releases(goreleaser, macOS/Linux/Windows) 바이너리 + 설치 스크립트 + Homebrew tap. **[오너 결정: 바이너리 다운로드 방식]**
- 로컬 설정·세션 토큰은 `~/.config/masil/` 에 저장(파일 권한 600).
- 서버 주소는 기본값 내장 + 설정/환경변수로 변경 가능(자체 호스팅 대비).

### 5.2 서버 **[오너 결정: Cloudflare 백엔드] / 세부는 [내 결정]**
- Cloudflare Workers (TypeScript, Hono) — REST API
- Durable Objects — 실시간 WebSocket(Hibernation API). 클라이언트당 소켓 1개로 모든 방·DM 이벤트 수신. 정확한 DO 분할(사용자별/방별)은 **[빌더 재량]**, 단 방 멤버 수가 수백 명이어도 팬아웃이 무리 없어야 한다.
- D1 — 사용자·관계·방·채널·메시지·글 등 영구 데이터
- R2 — 이미지(아바타·사진 글·스토리)
- Cloudflare 계정은 이미 **Workers Paid** 플랜. **[오너 확인]**
- 인증: 비밀번호는 PBKDF2(WebCrypto, 충분한 반복 횟수) 해시, 로그인 시 불투명 세션 토큰 발급(서버측 저장, 폐기 가능).
- 속도 제한: Workers Rate Limiting 바인딩 또는 DO 기반.
- 스토리 만료 등 주기 작업: Cron Trigger.

### 5.3 품질
- 서버: vitest + `@cloudflare/vitest-pool-workers` 로 API·DO 통합 테스트.
- 클라이언트: Go 단위 테스트 + `teatest` 골든 테스트 — 특히 **여러 창 크기(예: 200×60, 120×40, 80×24, 50×20)에서 화면이 깨지지 않는지** 스냅샷으로 검증.
- 로컬 개발: `wrangler dev` + 클라이언트를 로컬 서버에 연결해 엔드투엔드 확인.

## 6. 운영·배포 절차 (오너 윤허 필요)

- GitHub: `patrache/masil` 레포 생성 — 오너 요청에 따름. **개발 중엔 비공개**, 첫 출시 때 공개(오픈소스)로 전환. 사용자는 소스가 아니라 **GitHub Releases 바이너리**(설치 스크립트, Homebrew tap)로 설치 — 소스 공개와 바이너리 배포는 양립함. 라이선스(MIT: 자유 / AGPL: 남이 서버를 고쳐 비공개로 운영 못 함)는 공개 전환 시 오너가 결정. **[내 제안 — 오너 확인 대기]**
- Cloudflare 실제 배포(D1·R2·Worker 생성, `wrangler deploy`)는 **되돌리기 어려운·과금 가능 작업이므로 배포 직전 오너에게 건별로 여쭙는다.** 개발·테스트는 로컬 `wrangler dev` 로 진행.
- 기본 도메인은 `*.workers.dev`. 커스텀 도메인은 추후.

## 7. 개발 방식

- 오너 요청에 따라 계획(superpowers:writing-plans) 수립 후 **울트라코드(멀티 에이전트 워크플로우)** 로 병렬 개발. **[오너 결정]**
- 서버와 클라이언트는 **API·이벤트 계약(공유 스키마 문서)** 을 먼저 고정한 뒤 병렬로 개발한다. 계약은 3장 전체 범위를 처음부터 담는다(나중에 계약을 다시 여는 일을 피함).
- **만드는 순서(마일스톤)** **[내 결정]** — 전부 이번에 만들되, 앞 단계가 돌아가야 다음으로:
  - M1 기반: 계정·인증·세션, 실시간 소켓, TUI 뼈대(4개 레이아웃 모드·테마 4종·명령 팔레트)
  - M2 채팅: 친구·DM·그룹 DM, 방·채널·초대, 스레드·리액션·멘션·수정/삭제·고정·안 읽음·입력 중·접속 상태·검색
  - M3 SNS: 피드·답글·좋아요·리포스트·인용, 팔로우·프로필, 사진 글·스토리, 해시태그·트렌드, 알림함
  - M4 재미·운영: 투표·방명록·상태 메시지·집중 모드·슬래시 명령·데스크톱 알림, 차단·신고·운영자 기능

## 8. 빌더에게 맡기는 것

- 정확한 DB 스키마, API 경로 명명, DO 분할 방식, 반응형 중단점 수치, 키맵 세부, 이미지 렌더 라이브러리 선택, 페이지 크기 등.
- 단, 4장(TUI 품질)·2장(관계/권한 규칙)·1장 안티골은 지켜야 한다.
